##  Lock & Condition

### 1. 생산자-소비자 문제의 비효율
- 문제: `wait() / notify()` 방식은 **대기 집합이 하나뿐** → 생산자가 생산자를 깨우거나, 소비자가 소비자를 깨우는 비효율 발생.
- 해결: **Condition**을 사용하여 **생산자 전용 / 소비자 전용 대기 공간**을 나눈다.

### 2. Condition 활용
- `ReentrantLock`을 기반으로 `Condition` 객체 생성 가능.
- 생산자 메소드:
  - 버퍼가 꽉 차면 → `producerCondition.await()` (생산자 전용 대기 공간에서 대기)
  - 소비자 깨우기 → `consumerCondition.signal()`
- 소비자 메소드:
  - 버퍼가 비면 → `consumerCondition.await()` (소비자 전용 대기 공간에서 대기)
  - 생산자 깨우기 → `producerCondition.signal()`

=> 이렇게 역할별 대기 공간을 나누면 불필요하게 잘못된 스레드를 깨우는 비효율을 줄일 수 있음.

##  스레드 대기 상태 정리

### 1. `synchronized`의 대기 상태
- **BLOCKED 상태**: 다른 스레드가 락을 보유 중일 때, 락을 기다리는 스레드.
- **WAITING 상태**: `wait()` 호출 시, 현재 락을 반납하고 대기 집합(Wait Set)에서 기다림.
- 자바 내부적으로 `락 대기 집합`과 `wait set`이 따로 관리됨.

### 2. `ReentrantLock`의 대기 상태
- 락을 기다릴 때 BLOCKED 대신 **WAITING**으로 표현됨 → 관리와 제어가 더 유연.
- `Condition`을 이용하면 대기 집합을 세분화해서 활용 가능.

##  BoundedQueue 문제 해결 과정

1. **단순 큐 사용**
  - 버퍼 가득/비어있을 때 문제 발생.
2. **반복문 활용**
  - `while`로 확인 후 대기 → 하지만 락을 쥔 채로 대기 → 다른 스레드가 무한대기.
3. **wait()/notify()**
  - 락을 반납 후 대기 가능해짐.
  - 단, 대기 집합이 하나라서 **비효율** 발생.
4. **Lock + Condition**
  - 생산자/소비자 대기 공간 분리.
  - 잘못된 스레드를 깨우는 문제 해결 → 효율적.

##  BlockingQueue

자바에서 기본적으로 제공하는 **스레드 안전한 큐**.  
조건(가득참/비어있음)에 따라 **스레드를 차단(blocking)** 하여 불필요한 반복 체크나 `wait()/notify()` 코드 작성 불필요.

### 특징
- **큐가 가득 찼을 때**: 데이터 추가 시도 → 공간 생길 때까지 차단.
- **큐가 비었을 때**: 데이터 꺼내기 시도 → 데이터 들어올 때까지 차단.

### 주요 메서드
- `put(E e)`: 큐가 가득 차면 대기하다가 넣음.
- `take()`: 큐가 비어 있으면 대기하다가 꺼냄.
- `offer(E e)`: 큐가 가득 차면 즉시 실패 반환.
- `poll()`: 큐가 비면 즉시 실패 반환.

### 대표 구현체
1. **ArrayBlockingQueue**
  - 배열 기반, 크기 고정.
  - 생산자/소비자 간 **속도 차이가 큰 경우 적합**.
2. **LinkedBlockingQueue**
  - 링크드리스트 기반, 크기 제한 가능(없으면 사실상 무한).
  - 더 많은 데이터 저장에 유리.
