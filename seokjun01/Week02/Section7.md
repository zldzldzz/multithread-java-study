### 📚 동기화와 임계 영역

## 1. 동기화 (Synchronization)

동기화는 멀티스레드 환경에서 여러 스레드가 동시에 공유 자원에 접근할 때 발생하는 동시성 문제를 해결하는 과정.
대표적인 공유 자원은 인스턴스의 필드(멤버 변수), 동기화를 통해 데이터 불일치나 예상치 못한 동작을 막을 수 있음.

### 동시성 문제의 예시: 출금 예제

잔액이 1,000원인 계좌에 두 스레드가 동시에 600원을 출금한다고 가정
두 스레드가 모두 잔액을 확인하는 검증 로직을 통과하면, 잔액은 400원이 되어야 하지만, 실제로는 마이너스 잔액이 될 수도 있음

volatile 키워드의 한계:
volatile은 한 스레드가 값을 변경하면 다른 스레드에게 그 변경 사항이 즉시 보이게 하는 메모리 가시성 문제만 해결
동시성 문제 자체는 해결하지 못함!! 즉, 여러 스레드가 동시에 값을 읽고 쓰는 순서 문제를 막지는 못한다는 뜻

## 2. 임계 영역 (Critical Section)

임계 영역은 여러 스레드가 동시에 접근하면 데이터가 깨질 수 있는 위험하고 중요한 코드 부분. 
이러한 영역은 한 번에 하나의 스레드만 접근하도록 보호해야 해.

### 락(Lock)의 개념

자바는 모든 객체(인스턴스) 내부에 보이지 않는 **모니터 락(monitor lock)**을 가지고 있음.

synchronized 키워드가 붙은 메서드나 코드 블록에 진입하려면, 스레드는 반드시 해당 인스턴스의 락을 획득해야 함.

만약 다른 스레드가 이미 락을 가지고 있다면, 새로 진입하려는 스레드는 BLOCKED 상태가 되어 대기.
BLOCKED 상태의 스레드는 CPU 실행 스케줄링에서 제외.

메서드 실행이 끝나면 락을 반납하고, 대기 중이던 스레드 중 하나가 락을 획득함.
락을 획득하는 순서는 보장되지 x

### synchronized의 특징

synchronized 키워드를 사용하면 volatile을 따로 사용하지 않아도 메모리 가시성 문제가 해결돰
이는 락을 획득하고 해제하는 과정에서 캐시와 메인 메모리 간의 동기화가 이루어지기 때문.

## 3. synchronized 코드 블록

synchronized는 한 번에 하나의 스레드만 실행을 허용하기 때문에, 남용하면 병목 현상이 발생할 수 있음.
동시 실행이 가능한 부분과 그렇지 않은 부분을 구분하여 최적화하는 것이 중요.

자바는 메서드 전체를 동기화하는 대신, 특정 코드 블록만 동기화할 수 있는 기능을 제공.

synchronized(this)를 사용해 임계 영역을 설정할 수 있음.
*this는 현재 객체의 락을 사용하겠다는 의미.
