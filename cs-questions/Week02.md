# 2주차

석준 Q : `Thread.interrupted()`와 `Thread.isInterrupted()`의 차이는 무엇인가요?

석준 A : 

- `Thread.interrupted()`
    - 현재 스레드의 인터럽트 상태를 확인하고, **인터럽트 상태를 false로 초기화**
- `Thread.isInterrupted()`
    - 해당 스레드의 인터럽트 상태를 확인만 하고, **상태는 변경하지 않음**

준선 Q: **`volatile`** 키워드는 어떤 역할을 하나요?

준선 A: 

변수의 값이 CPU 캐시에만 머무르지 않고 **`메인 메모리`**에서 **`읽히도록 보장하는 역할`**을 합니다.

멀티스레드 환경에서는 각 스레드가 변수 값을 CPU 캐시에 따로 들고 있을 수 있는데, 이 경우 한 스레드가 값을 변경해도 다른 스레드가 캐시된 옛 값을 읽어버릴 수 있습니다. volatile을 선언하면 메인 메모리에서 읽어, 캐시 일관성 문제를 해결하여, **`메모리 가시성을 보장`**합니다.

---

💭원진 Q: `volatile`과 `synchronized`의 차이/공통점? 

💯원진 A:

## 공통점

### happens-before 보장

volatile: 같은 변수에 대해 “쓰기 → (다른 스레드의) 다음 읽기”가 happens-before.
synchronized: 같은 모니터(락) 에 대해 “unlock → (다른 스레드의) 다음 lock”이 happens-before.
-> 한 스레드의 결과가 다른 스레드에서 관측된다.

### 메모리 가시성

HB 관계를 통해 변경 사항이 다른 스레드에서 보이도록 보장합니다.

## 차이점

### volatile

 가시성과 (해당 변수 기준) 재정렬 방지는 보장하지만 배타적 실행과 복합 연산의 원자성은 보장하지 않는다.

### synchronized

 같은 모니터(락) 를 사용하는 코드 사이에서 배타적 실행과 가시성을 함께 보장한다.

- 차이점이 생기는 이유 (ex: i++ 연산)
    - `volatile` 의 경우 읽기 스레드를 대기시키지 않고 해당 변수의 **다음 읽기**의 값을 최신 상태로 보장한다.
    - `synchronized` 의 경우 쓰기 중인 스레드가 락을 쥐고 있는 동안 같은 락을 쓰는 다른 스레드의 접근을 블록하여 임계구역(`synchronized` 을 사용하는 구역)을 한번에 하나만 실행하게 만든다.

규민 Q: OS에서 인터럽트가 빈번하게 발생하면 어떤 현상이 생기나요?

규민 A: 인터럽트가 많으면 스레드 변경이 빈번하게 발생해서 컨텍스트 스위칭 또한 빈번하게 이뤄져서 스레드 컨텍스트를 저장이나 복원하는 과정이 많아져서 할당된 CPU 시간이 로직 처리에 집중을 못하게 되서 처리량이 떨어지는 성능 감소로 이어지게 됩니다.

---

채연 Q: 

interrupt의 목적과 흐름을 설명하세요. 

채연 A: 
(목적) interrupt의 목적은 특정 스레드의 작업을 중단하는 것입니다. 

(흐름) interrupt를 통해 대기 중인 특정 스레드를 깨웁니다. InterruptedException을 던지는 메서드를 호출하면, 예외가 발생하여 catch 내부의 로직이 실행됩니다.

기민Q:

자바의 Thread.interrupt()는 운영체제의 하드웨어 인터럽트와 어떤 점이 다를까?

기민 A:
**운영체제의 하드웨어 인터럽트는 CPU 실행을 강제로 중단하고 커널 핸들러를 실행하는 하드웨어·커널 레벨의 이벤트이고, 자바의 `Thread.interrupt()`는 스레드 객체에 “중단 요청” 신호를 남겨 협력적으로 종료를 유도하는 JVM 레벨 메커니즘이다.**

- 추가 내용
    
    ## 공통점
    
    - 둘 다 **실행 흐름에 "신호"를 보내서 현재 동작을 바꾸도록 유도**한다.
    - 직접 강제로 제어하는 게 아니라, **“중단 요청”을 전달**한다는 점에서 유사하다.
    
    ---
    
    ## 차이점
    
    ### 1. 동작 계층
    
    - **하드웨어 인터럽트 (HW Interrupt)**
        - CPU 외부 장치(디스크, 네트워크 카드, 키보드 등)가 **CPU에게 즉시 개입을 요청**하는 신호.
        - OS 커널이 하드웨어 인터럽트를 받아서 현재 실행 중인 작업을 중단하고 **인터럽트 핸들러(ISR)**를 실행한다.
        - 즉, **커널/하드웨어 수준**에서 동작한다.
    - **자바의 `Thread.interrupt()`**
        - JVM 내부에서 관리하는 **스레드 객체에 인터럽트 플래그를 세팅하는 것**.
        - 실제 OS 스레드에는 직접 개입하지 않는다.
        - 스레드가 차단 상태일 때는 `InterruptedException`을 발생시키고,
            
            실행 중이라면 스레드 코드가 스스로 `isInterrupted()` 같은 메서드를 확인해서 반응해야 한다.
            
        - 즉, **애플리케이션/JVM 수준**에서 동작한다.
    
    ---
    
    ### 2. 강제성
    
    - **하드웨어 인터럽트**는 **강제적**이다. CPU는 무조건 현재 실행을 멈추고 인터럽트 핸들러로 점프해야 한다.
    - **자바 interrupt**는 **비강제적**이다. 단순히 “신호만 보내는 것”이라서,
        
        스레드 코드가 무시하면 그냥 계속 실행된다.
